01 · Problem

Useful knowledge should be easy for an AI assistant to access—without moving it to the cloud.

Scattered information

Notes and FAQs can be stored locally but still be difficult to search naturally.

Manual retrieval

Users should not need to manually open JSON files and scan them for every answer.

Privacy & portability

The runtime should work without a database or external API and keep data under local control.

02 · Architecture

A small, explicit path from natural language to local data.

Host Claude Desktop Natural-language request
→
Protocol MCP Server stdio · TypeScript
→
Validation Zod v4 Validated tool inputs
→
Storage Local JSON notes.json · faqs.json
No cloud database is required. The MCP server reads local fixture data and exposes focused tools and resources over stdio.

03 · Core Tools

The notes-side capabilities used in the live demo.

search_notes

Search notes

Searches locally stored notes using validated keywords with bounded result limits.

query · limit?
get_note

Get one note

Retrieves the full content of a known note by validated note ID.

note_id
list_notes

List notes

Lists notes with optional tag filtering and a bounded result limit.

tag? · limit?
Read-only resource notes://index

Exposes a structured notes index to an MCP client without changing stored data.

04 · Offline-First Runtime

The server does not depend on a cloud service to execute its tools.

What stays local

  • Tool handlers
  • Input validation
  • Notes and FAQ data
  • Search and retrieval logic
  • Validated note writes

Offline verification

With Wi-Fi disabled, MCP Inspector can still start the local stdio server, list its tools, and call tools against the local JSON data.

Claude itself still requires connectivity to the Claude service; the offline claim applies to our MCP server runtime.
